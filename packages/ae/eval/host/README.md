# Qualify installed Engineer delivery

Run this protocol in a disposable product checkout. Keep the model and any agent subprocess in the editor host. Record an unavailable step as unavailable. Do not replace it with a scripted model response.

## Prepare a controlled trial

1. Pack the candidate package and record its revision, archive integrity, Node version, host version, and operating system. Install that archive outside the source checkout.
2. Hydrate a private Copilot home. Use a private AE home and a linked product worktree. Preserve the user's global installation and existing work.
3. Register the candidate agents, skills, instructions, and hooks through the selected host's supported configuration. Confirm that the selected Engineer comes from that installation. Record any home mapping or operator assistance.
4. Define the product behavior, allowed files, preservation checks, named verification check, and verification recipe before approving the check manifest. Create and start an accepted plan through the installed CLI.
5. Run the product's acceptance check before the agent starts. Preserve its failing output and the exact source bytes. Keep the evaluator and preservation expectations outside the agent's editable scope.

The October 20 trial used catalog title search. The accepted behavior ignored query case and surrounding whitespace, returned all products for a whitespace-only query, and preserved product data and order. The only allowed files were `src/catalog.mjs` and `test/catalog.test.mjs`. The named check ran `node --test test/catalog.test.mjs`. A CLI recipe also exercised `" notebook "`, `" PEN "`, and `"   "`.

## Drive the native Engineer

1. Select the installed Engineer in the actual host. Record the requested model and any reported resolved model. Auto routing is a diagnostic selection, not a controlled model comparison.
2. Ask it to continue the accepted plan, repair the failing behavior, collect required review, run fresh named verification, record learning or no-learning, and complete only with current proof.
3. After orientation or an edit, cancel the host turn. Preserve the transcript, source diff, plan revision, gate state, and evidence references. Resume with a new request that names the same accepted plan.
4. In a separate stale-source phase, change a selected spec in the controller. Confirm that the implement gate rejects the changed bytes. Have the Engineer inspect the change and submit an explicit intent amendment before another edit. Do not silently relock or renew proof.
5. Preserve native review results and actual invocation provenance. Run named verification after the final edit. Confirm learning or no-learning, plan completion, and the host's Stop result.
6. Independently rerun acceptance and preservation checks after the agent stops. Record unexpected files, command denials, manual interventions, omitted evidence, and failed attempts.

## Retain evidence

Keep the archive integrity, fixture commits, source hashes, setup receipt, model metadata, transcript export, hook decisions, plan operations, review record, named verification record, learning decision, completion receipt, and final independent check. Use an external artifact directory so receipts do not change the product under test.

A completed native trial requires both correct product behavior and current lifecycle proof. A partial fix, a passed command, a final chat message, or a model-free fixture is insufficient. macOS proof does not qualify Windows or IntelliJ. Host restart and compaction require actual host observations beyond CLI journal recovery.

## Compare workflow and context changes

Freeze acceptance, preservation checks, model, host, and budgets before comparing variants. Change one factor at a time. Record all attempts, model usage where available, elapsed work, tool calls, repairs, and operator interventions. Follow the existing context protocol's held-out thresholds before changing a default.

The context dry run validates broken baselines and context packaging. Mechanical extraction trials count observed CLI calls and bytes. Neither measures model quality, reasoning overhead, token savings, or native recovery. If those observations are missing, keep the comparison inconclusive and leave policy defaults unchanged.
