Install the built Harness package in a clean home outside the source checkout. Discover the installed skill and run doctor using that home. Declare a named argv check in the product's trusted check configuration; the product adapter owns assertions, setup and cleanup. Keep product fixtures out of the global skill.

Capture the following evidence against the same product contract: broken behavior → verify is non-passed → enforcing installed Stop is blocked; repaired behavior → fresh passed verify → allowed Stop. Preserve the returned proof and completion records. Required review must be collected, and learning/no-learning must be recorded before completion.

Report local executable proof, platform CI, doctor fixture probes and live host invocation separately. Missing product access or an untested host remains unverified. Do not claim delivery from copying a skill, declaring a check or obtaining a green unrelated test.

Use the installed [product-proof.mjs](../harness-doctor/scripts/product-proof.mjs) with an authored [feature map](../harness-doctor/references/product-flow-map.example.json) in the product workspace. The example intentionally fails until product, environment and acceptance are selected. Map checks to the product's actual named argv checks and the plan's criteria. The adapter owns setup, assertions, safe break/repair and cleanup. This entry executes no arbitrary setup commands and supplies no reviewer or learning judgment.

Run the entry with `--workspace <product> --copilot-home <clean-home> --plan <plan-path> --map <relative-map> --stage broken`, then repeat with `--stage fixed` after repair, review, passed verification, learning/no-learning and completion. Optional --harness-home selects the same private store used throughout the journey; relative paths resolve once from the entry's working directory. Record a successful governed edit through the real host or the adapter's explicitly observed hook invocation before the negative Stop proof. The installed recorder binds the edit to its active plan. Both stages require the same selected plan, recorded edit and proof in the session before invoking Stop. Upgrade old recorders and observe a new edit before this proof; a missing mutation record cannot prove interception.

The script delegates bounded retrieval, doctor and factual completion validation to the installed Harness, and invokes its installed Stop hook without HARNESS_BIN fallback. The broken stage executes verify and requires an actual mapped check failure plus blocked Stop. The fixed stage validates and retrieves the bound execution record; it requires every mapped check passed, current proof/completion and allowed Stop. Run repaired verification before learning and completion: reverifying after completion creates new proof and correctly makes its previous learning binding stale. Capture the bounded JSON output alongside underlying source records. A synthetic fixture certifies this executable entry; it leaves selected-product and live-host acceptance pending.
